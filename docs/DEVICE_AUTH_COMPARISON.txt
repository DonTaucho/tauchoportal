================================================================================
SMART DEVICE AUTHENTICATION: QUICK COMPARISON
================================================================================

TIER 1: LOGIN-ONLY (Best UX - User Never Enters API Keys)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🥇 TUYA - Score 4/5 ⭐ RECOMMENDED

   USER EXPERIENCE:
   ┌─ Click "Login with Tuya"
   ├─ QR code shown (or OAuth popup)
   ├─ User scans with Smart Life app (or approves in popup)
   ├─ Returns to app automatically
   └─ Devices pre-populated ✨

   WHAT'S AUTO-DISCOVERED:
   ✅ Device list (all user's devices)
   ✅ Device names
   ✅ Device capabilities (brightness, color, modes)
   ✅ Product category
   ✅ Online status
   ✅ Regional endpoint (for cloud API)

   CRITICAL CONSIDERATIONS:
   ⚠️  Must register app at platform.tuya.com (you get a client_id)
   ⚠️  API is tiered pricing (free tier has quota limits)
   ⚠️  Token refresh needed (tokens expire)
   ⚠️  Whitelist of thousands of Tuya-compatible brands

   IMPLEMENTATION: Medium complexity
   - OAuth 2.0 token exchange
   - Store encrypted refresh token
   - Auto-list devices on login
   - Refresh token when expired

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TIER 2: HYBRID (One-Time Paste + Auto-Discovery)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🥈 GOVEE - Score 3/5

   USER EXPERIENCE:
   ┌─ Open Govee app → Settings → "Apply for API Key"
   ├─ Email sends key
   ├─ User pastes key into your app
   ├─ Your app fetches devices automatically
   └─ Done! ✨

   WHAT'S AUTO-DISCOVERED:
   ✅ Device list
   ✅ Device IDs (MAC format)
   ✅ Device capabilities (full schema)
   ✅ Product SKU/model

   GOTCHA: 
   ⚠️  ONLY ONE active key per account (May 2026 change)
   ⚠️  Generating new key invalidates old one
   ⚠️  Beta API (no SLA)

   IMPLEMENTATION: Low complexity
   - Store API key (encrypted)
   - Call REST API to list devices
   - No token refresh needed


🥈 LIFX - Score 3/5

   USER EXPERIENCE:
   ┌─ Visit cloud.lifx.com/settings
   ├─ Generate "Personal Token"
   ├─ Paste into your app
   ├─ Your app fetches devices automatically
   └─ Done! ✨

   WHAT'S AUTO-DISCOVERED:
   ✅ Device list
   ✅ Device names (labels)
   ✅ Device state (brightness, color)
   ✅ Group/location info
   ✅ Capability flags (has_color, has_variable_color_temp)

   GOTCHA:
   ⚠️  No OAuth redirect flow (manual token generation)
   ⚠️  Devices must be cloud-connected
   ⚠️  Future uncertain (acquired by Feit Electric)

   IMPLEMENTATION: Low complexity
   - Store Bearer token (encrypted)
   - Call REST API to list devices
   - Clean, well-documented API


🥈 PHILIPS HUE - Score 3/5 (local) / 4/5 (if approved for remote)

   USER EXPERIENCE (Local):
   ┌─ Press button on Hue Bridge
   ├─ System auto-discovers bridge (mDNS or HTTP discovery)
   ├─ Devices auto-listed from bridge
   └─ Done! ✨

   WHAT'S AUTO-DISCOVERED:
   ✅ Device list (from local bridge)
   ✅ Device state
   ✅ Capabilities

   GOTCHA:
   ⚠️  Hardware required (~$60 bridge)
   ⚠️  Must be on same LAN as bridge
   ⚠️  Remote API gated behind Signify approval (uncertain timeline)
   ⚠️  Self-signed certs on bridge

   IMPLEMENTATION: Medium complexity
   - mDNS discovery or HTTP discovery.meethue.com call
   - Button pairing flow
   - Self-signed cert handling

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

TIER 3: LOCAL-ONLY (No Cloud, LAN Discovery Required)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔴 NANOLEAF - Score 2/5

   USER EXPERIENCE:
   ┌─ Press button on device for 5 seconds
   ├─ System discovers device on LAN
   ├─ Gets local auth token
   └─ Works on same network only ❌

   DRAWBACK: No remote access, requires physical interaction


🔴 YEELIGHT - Score 2/5

   USER EXPERIENCE:
   ┌─ User enables "LAN Control" in Yeelight app
   ├─ System discovers device via SSDP on LAN
   └─ Works on same network only ❌

   DRAWBACK: Unencrypted LAN protocol, no cloud access


🔴 TP-LINK KASA/TAPO - Score 2/5

   USER EXPERIENCE:
   ┌─ System discovers device via UDP broadcast on LAN
   ├─ Gets device info
   └─ Works on same network only ❌

   DRAWBACK: No public cloud API, local-only


🔴 WLED - Score 1/5

   USER EXPERIENCE:
   ┌─ User must know device IP
   ├─ Enter IP manually
   └─ Works on same network only ❌

   DRAWBACK: No user accounts, no cloud, purely local DIY firmware

NOT FEASIBLE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ AMAZON ALEXA - Score 1/5 (Wrong Paradigm)

   WHY: Alexa is a platform you BUILD FOR, not a cloud you query
   - You create a Skill that *receives* discovery requests from Alexa
   - You integrate device brands *inside* your Skill
   - Backwards from the desired flow

   RECOMMENDATION: Skip for device cloud integration


❌ WYZE - Score 2/5 (Unstable)

   WHY: Reverse-engineered unofficial API
   - Can break with app updates
   - Rate limiting on auth
   - No official documentation
   - Developer program appears defunct

   RECOMMENDATION: Last resort if needed by users

QUICK DECISION TREE
================================================================================

Want "User logs in, devices appear automatically"?
├─ YES, want best experience?          → Implement TUYA (Tier 1)
├─ YES, but low implementation effort? → Implement GOVEE (Tier 2)
├─ YES, want multiple providers?       → TUYA + GOVEE + LIFX (all Tiers)
├─ YES, but users on same LAN?         → Add HUE/KASA local (Tier 3)
└─ Want all supported?                 → Tier 1 + Tier 2 (skip Tier 3 for now)

================================================================================
IMPLEMENTATION RECOMMENDATION
================================================================================

PHASE 1 (Highest Impact):
  → Tuya (4/5) — Best "login-only" UX, massive ecosystem
  → Govee (3/5) — Easiest to implement, fast wins

PHASE 2 (Expand Coverage):
  → LIFX (3/5) — Great API quality
  → Philips Hue (3/5) — Local works now, remote later

PHASE 3 (Nice-to-Have):
  → Nanoleaf, Yeelight, TP-Link (local-only if users demand)

DO NOT IMPLEMENT:
  → WLED, Amazon Alexa, Wyze (wrong paradigm or too risky)
