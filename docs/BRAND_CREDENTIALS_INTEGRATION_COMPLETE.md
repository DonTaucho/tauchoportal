## 🎯 How It Works

### User Flow
1. User visits `/brand-settings` (requires authentication)
2. Page loads all brands via `GET /auth/brands`
3. Each brand displayed with "Connect", "Manage", or "Disconnect" button
4. User clicks "Connect"
5. Modal opens and loads credential fields via `GET /auth/brand/{id}`
6. User fills fields and clicks "Test Connection"
7. Frontend calls `POST /auth/brand/{id}/test` (no save)
8. Shows result: "✅ 12 devices found" or "❌ Invalid API key"
9. If valid, user clicks "Connect"
10. Frontend calls `POST /auth/brand/{id}/connect` (saves credentials)
11. Page reloads, brand now shows "Connected" and "Manage"/"Disconnect" buttons

## 🔧 API Requirements

### Authentication
All requests require `X-User-ID` header:
```javascript
headers: {
  'X-User-ID': userId,
  'Content-Type': 'application/json'
}
```

### Credential Field Format
Backend returns credential fields for each brand:
```json
{
  "credential_fields": [
    {
      "name": "api_key",
      "label": "API Key",
      "type": "password",
      "required": true,
      "help": "Get from app settings"
    }
  ]
}
```

Frontend dynamically renders form based on this.

### Status Values
- `"connected"` - Credentials active
- `"expired"` - Token expired (OAuth)
- `"revoked"` - User revoked access
- `"invalid"` - Failed validation
- `null` - Not connected
